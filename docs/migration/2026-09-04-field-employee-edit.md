# 地块与人员编辑修复（测试环境）

## 根因与修改

- 地块编辑请求的 `GET /smart-farming/field/{fieldId}/detail`、`/{fieldId}/batch-info` 未在迁移后的 Controller 暴露。补回原路径，由 Service 聚合当前租户可见的地块、批次和设备摘要；不忽略租户过滤，不更改授权数据。
- 地块弹窗将 `display:flex !important` 放在居中定位的 Modal 根节点上，破坏其 inline-block 对齐。改用 Modal 的宽度与内容容器布局，保持表单和大棚布局独立滚动。实测弹窗从屏幕下方 y=720 恢复到 y=36、height=648（720 高视口）。
- 表单选项刷新时，默认值先原地覆盖了 values，造成已回显的大棚重置为大田。保留当前值快照后合并默认值。
- 表单变更回调统一传字段名数组，修复地块页 `fieldsChanged.includes` 联动错误。
- Zod 对象不能直接传入 antdv-next FormItem.rules；转换为异步 validator 数组，保留原校验消息。校验不通过不执行提交回调。
- 人员档案不再加载或保存后端已明确废弃的工人技能接口，显示废弃说明，基础人员档案编辑不受影响；没有重新开放旧派工接口。
- 组合应用重新点击当前菜单或标签时，显式导航子应用回到对应列表。保留原有授权菜单范围。
- 地块详情失败时关闭未完成表单并释放 loading；行政区划失败允许手动填写。替换地块相关 Modal 废弃属性。
