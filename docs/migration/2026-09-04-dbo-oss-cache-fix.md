# DBO 企业 Logo 上传配置缓存修复

## 故障证据

- DBO `/resource/oss/upload` 日志先出现 `127.0.0.1:9000` 连接拒绝，随后出现 `'ymclod-sf'配置信息不存在`。
- 当前 DBO 主数据源为 `ry_dbo`，独立 Redis DB 为 2。`ry_dbo.sys_oss_config` 已存在默认状态 `Y` 的 `ymclod-sf`，endpoint 为 `oss.agi.cqmcloud.com`。
- 修复前 Redis 默认标识为 `ymclod-sf`，但 DBO 全局 OSS 配置缓存缺少对应条目。
- 原默认切换逻辑只更新默认标识，未加载数据库中的完整配置；数据库导入配置后切换默认时会暴露该问题。

## 修改范围

- 仅修改 DBO OSS 初始化、默认配置切换及事件监听器，不改 SaaS/农业/工业配置，不修改数据库配置值。
- 默认切换根据配置主键重新读取 DBO 数据库记录，使用数据库中的配置标识和完整配置，不采用前端提供的配置标识。
- 默认变更事件携带完整配置；先写配置缓存、移除旧客户端，再发布默认标识。
- 启动初始化同样先写完整配置，再设置默认标识。
- 配置不存在时，在重置默认状态前拒绝操作。

- Maven 定向测试及 package 成功。
