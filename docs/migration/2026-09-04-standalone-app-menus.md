# 独立微应用菜单范围修复

## 原因与变更

- 农业 5670、物联网 5671 独立模式原先调用 `/system/menu/getRouters`，得到全系统授权菜单；无界嵌入使用 SaaS `/system/app/authorized` 返回的源应用菜单，两者范围不同。
- 两个子应用现在均复用 `/system/app/authorized`，分别选择 `agriculture`、`iot` 的源菜单与按钮权限。无界嵌入继续只接受宿主下发的当前应用切片。
- 兼容只开通组合应用的租户：合并已授权组合应用中的同源菜单，按目录递归去重并保留已知相对顺序。不会读取未授权的源应用全量菜单；多个授权组合的并集可能大于某一个组合，这属于不同入口的授权范围差异。
- 菜单深拷贝后交给路由转换，避免路由路径拼接污染原始上下文。授权无匹配时返回空菜单/空权限，接口失败时不回退全系统菜单，不缓存跨租户授权。
- 两种运行模式均不额外暴露模板导航；保留隐藏启动页、个人中心和业务详情路由。独立登录和布局保留。
- 无数据库、套餐、角色授权变更，无 DBO 或 SSO 改动。遵循 ruoyi-plus-ai-coding 技能并复用实际工程的 Alova 请求层。

## 修改位置

两个独立项目均修改：

- `src/api/core/app-access.ts`：筛选与合并已授权源应用。
- `src/api/core/menu.ts`：独立/无界双模式授权入口。
- `src/stores/auth.ts`：登录、刷新用户信息时使用当前应用按钮权限。
- `src/router/guard.ts`：菜单仅来自应用授权，保留隐藏辅助路由。
- `src/api/core/app-access.test.ts`：10 项回归测试。
